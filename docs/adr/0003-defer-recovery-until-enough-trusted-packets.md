# Defer recovery until enough trusted packets accumulate; bit-flip search is the fallback

[ADR-0002](0002-recovery-solves-linear-system-instead-of-bitflip-search.md) left open what to do when the linear system is underdetermined (`K` candidate columns, fewer than `K` independent trusted rows). Decision: don't treat this as a hard failure — wait for more packets to arrive in the generation (RLNC receivers normally accumulate more coded packets than `gen_size` anyway). Once enough trusted rows exist to make the system solvable, solve it exactly per ADR-0002. Bit-flip search is now only the fallback for the case where the system is still underdetermined (e.g. a latency budget forces recovery before enough packets have arrived).

This trades latency for solvability — waiting costs time the thesis's latency/throughput metrics care about. For now, recovery waits **indefinitely** (no timeout), justified by the assumption that upstream RLNC nodes keep sending packets until signaled "done," so scarcity isn't a real failure mode — deliberately keeping complexity low for this design pass. A latency ceiling that triggers an earlier fallback is a possible future addition if there's capacity for it later. Not addressed: a generation where corruption is high enough that the trust threshold ([ADR-0004](0004-sniffing-trust-model.md)) can never be met no matter how long you wait — waiting indefinitely only helps when the bottleneck is time, not when it's corruption rate.
