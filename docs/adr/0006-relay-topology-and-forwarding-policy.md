# Relay topology is a fixed branching shape; relays use a hybrid buffer-then-on-the-fly forwarding policy

For the first throughput/KPI sweep, only field size and generation size are swept parameters — topology itself (branching factor, hop depth) is not, so the network shape needs one fixed, representative choice. We picked Source → 2 parallel Relays → Sink over a single linear hop because one relay never exercises recoding from multiple paths, which is the RLNC behavior actually under study; a deeper chain was rejected for now as unnecessary complexity until topology itself becomes a swept variable in a later pass.

Relay forwarding policy sits between the two textbook extremes. Pure on-the-fly recoding (forward as soon as ≥1 packet is received) minimizes latency but risks early recoded packets being linearly dependent — useless to downstream nodes. Waiting for full rank before forwarding anything guarantees every outgoing packet is useful but adds a full generation's worth of latency at every hop. Instead, each Relay buffers until it has received a fixed **3** packets, then recodes and forwards from its still-growing buffer every tick onward. The threshold (3) is a constant for this pass, not swept — revisit if the KPI results turn out to be sensitive to it.
