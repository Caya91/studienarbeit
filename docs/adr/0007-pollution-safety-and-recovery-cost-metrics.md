# Safety evaluation injects random and detection-evading pollution and measures recovery correctness, silent-failure rate, and field-op cost

The clean-channel KPIs (ADR-0005, ADR-0006) measure throughput but exercise none of the sniffing/ACR/recovery pipeline, so they say nothing about how the algorithm behaves under attack. We need a second family of experiments that pollutes packets, runs `recover_generation` (`playground/new_recovery.py`), and quantifies three things: how many corrupted packets are correctly repaired, how often a *wrong* packet is silently accepted, and how much computation the recovery costs. Because the harness generates the packets itself, it holds ground truth — the pre-pollution generation — and can grade every recovery against it rather than trusting the algorithm's own "recovered" verdict.

Decision: two attacker models. **Random** pollution reuses the existing `pollute_full_packet` / `pollute_data_packet` / `pollute_tags_packet` (`binary_ext_fields/pollution.py`) as the baseline — an attacker with no knowledge, corrupting uniformly random bytes. **Intelligent** pollution is *detection-evading*: the attacker crafts a corrupted packet aimed at satisfying the acceptance oracle (ADR-0001) while still differing from the true packet. This is grounded in ADR-0002's observation that any single cross-tag equation always has a solution, so "it passed a check" is never proof of correctness; the interesting measurement is how often a crafted packet slips the *full-generation* orthogonality oracle, not the self-tag alone. The detection-evading attacker assumes worst-case (white-box) knowledge of the tag structure, which must be stated per experiment — a genuinely black-box attacker is not expected to beat the ~`1/field_size` baseline, and measuring that gap is itself a result.

Decision: the **primary safety KPI is the silent-failure rate** — packets the pipeline accepted (passed the oracle, written back into the pool) that do not equal ground truth, over the number of polluted packets. Per ADR-0001, a silently wrong recovery is worse than no recovery, so this is the safety-critical number, not the raw recovery rate. Secondary KPIs, all computable from the same per-packet classification `(polluted?, flagged-by-sniff?, recovered == truth?)`: recovery rate (correctly repaired / polluted), detection rate (flagged polluted / polluted, i.e. sniffing sensitivity), and false-positive rate (flagged clean / clean, which costs throughput even when safe). The `recover_generation` status (`waiting` / `recovered` / `partial`) is recorded but is not itself a safety metric — it is the algorithm's self-report, and the whole point is to check it against ground truth.

Decision: recovery cost is measured as a **field-operation count** (finite-field multiplications and additions consumed during recovery), not wall-clock time, for the same reason ADR-0005 rejected wall-clock for throughput — to isolate the algorithm's intrinsic cost from OS/Python scheduling noise and keep results deterministic. Since every multiplication in the codebase funnels through `TableField.mul` / `TableField.add`, instrumentation is a thin counting wrapper (a `CountingField` subclass overriding `mul`/`add` to increment a counter) passed into recovery only during measurement, leaving the production field untouched. Cost is reported per recovery attempt and per successfully recovered packet, and is expected to scale with `K`, the number of candidate corrupted columns ACR localizes, and to jump when the bit-flip fallback (ADR-0003) is triggered — so the fraction of recoveries taking the fallback path is recorded alongside.

Decision: keep the three-layer separation the throughput sweep already uses. A standalone trial harness produces raw counters, a `recovery_kpi_metrics` module derives per-trial KPIs and aggregates them (mean ± standard error, filtering trials the way `summarize` already filters non-converged ones), and a sweep script sweeps the new axes — pollution rate, attacker model, field size, generation size. The harness starts standalone rather than being wired into `network_sim`'s tick loop: recovery operates on a *pool* of packets, not the per-tick link transmission, and ADR-0005 already anticipated pollution becoming a swept axis of the tick simulator later. Merging the two — so a polluted channel also shows its throughput cost in extra ticks — is deferred; the trade-off is that this first pass measures recovery correctness and cost in isolation and does not yet show pollution's effect on goodput.
